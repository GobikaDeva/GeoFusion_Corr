GeoFusionNet / GeoCorr: Revised Research Direction

Proposal for approval · 2026-10-10 · main @ 5572daf · Gobika S
Summary. The original thesis was that a monocular-anchored geometry prior, fed to the network as an input (GeoFusionNet's GGF) and then used to correct the matching score (GeoCorr Lite), would fix the failures of self-supervised MVS. The first half was tested and gave no measurable gain. The prior is nearer the true cost dip on only 52.4% of failure pixels and within 4 mm of ground truth on only 11.5%. The frozen Stage 0 baseline A0f scores 0.437 / 0.545 / 0.491 (acc / comp / overall, mm, 3 seeds × 22 scans, 1600×1152). The one large measured gain came from capacity: C1_capacity scores 0.418 (seed 2) and 0.414 (seed 0), against 0.479 for A0f seed 2.
The revised direction makes the empirical study of what limits self-supervised MVS the primary track (Track 2). The frozen-monocular-feature run is an exploratory screen (Track 1). GeoCorr Lite (Stage 2) has never been run. It is proposed as the next experiment, not reported as a result.
Conventions. All numbers are measured, from runs/, unless marked PENDING (not yet measured) or NOT RUN. Fused point-cloud scores use DTU test (22 scans), 1600×1152 input, GeoMVSNet's fusion and the official DTUeval protocol, in mm (lower is better), unless stated otherwise. Naming: the queue's run B2_capacity is reported here as C1_capacity (C1). This avoids a collision with the manuscript's B2, which is GeoCorr Lite. Run directories keep their original names (runs/B2_capacity/, runs/B2_nogeo/, runs/B2_mono_feat/). B2_nogeo and B2_mono_feat are C1-size models.

1. What was done, from the start

1.1 The original plan (manuscript thesis)

Thesis: geometry-aware self-supervised MVS. A self-supervised cascade network (GeoFusionNet) is given an external metric geometry prior G. G enters in two ways, each added as a zero-initialized residual so that any gain can be attributed:

  • GeoFusionNet (Stage 1): geometry-guided feature fusion (GGF). A separate geometry encoder turns G into features that are added to the reference-view features before the cost volume (representation level). L_geo, a loss pulling predicted depth toward G, is also part of the objective.
  • GeoCorr Lite (Stage 2): a residual on the raw matching-score volume, score + α · gate · energy. The energy comes from a few scalar geometric compatibility maps through one shared 1×1 head, and α starts at 0. This changes which depth hypothesis wins (scoring level).
  • Staged rule: no architectural comparison counts until Stage 0 is frozen and measured over 3 seeds.

Prior G: Depth-Anything-V2-Small relative inverse depth, fitted per view to metric mm by RANSAC on 1/z = s·g + t against SIFT points triangulated with the known DTU cameras (no ground truth is used). Views with too few anchors, mainly on textureless scans, get no prior.

2. The baseline and the current model

2.1 Architecture

Both models are 3-stage CasMVSNet-style cascades over 1 reference + 4 source views at 640×512 in training. Each stage warps source features onto fronto-parallel depth planes with a differentiable homography, builds a cost volume, regularizes it with a 3D CNN, and regresses depth by soft-argmin (softmax expectation). Later stages search a narrowed range around the up-sampled previous depth.

3. Why the direction changed

The geometry prior, fed through a separate encoder (GGF), did not help. In a matched pair against an identical control, B1 changed validation and scan48 depth by less than the control's own checkpoint-to-checkpoint swing, and it did not move the competing-dips share. The measured reason: at the pixels where the model fails, the prior is not reliable enough to choose between the competing depth hypotheses.

3.1 What the failures are

The errors concentrate on scans 11, 13, 48, 62 and 77. On scan48 (A0f seed 2, 640×512), 42.9% of valid pixels are wrong (> 4 mm). At those pixels the raw cost curve has the GT depth as a secondary local minimum ("competing dips") on 18.75% of valid pixels, and the photometric loss itself prefers the wrong depth on most wrong pixels. Across every training change at A0f size, the competing-dips share stayed at 18.4–20.0%. The image evidence alone cannot decide, so the original plan turned to an external prior.

3.3 Gating the prior does not rescue it end to end

A gate was accepted only if, with thresholds fit on the 18 validation scans and frozen, it covered ≥ 20% of ambiguous test pixels at ≥ 80% correct-dip rate (pre-registered). Of six single signals (both orientations) and a logistic combination, only one passed:

The passing gate is partly mechanical: it fires where G disagrees with the model by ~100 mm, i.e. on gross outliers. The A0f gain (−0.009) equals A0f's seed std (0.009), and almost all of it comes from scan48 (−0.116) and scan77 (−0.114); the other 20 scans are slightly worse in sum (+0.024). On C1 the gain is −0.003.

3.4 What did move the result

Capacity. C1_capacity (17× more parameters on the depth path) improved fused overall from 0.479 to 0.418 at seed 2 and reached 0.414 at seed 0. This came with lower completeness error (0.362 vs 0.523). Per-view depth maps did not improve (§4.1(b)), and why C1's depths fuse better is not yet explained.

4.3 Not a track: GeoCorr Lite

GeoCorr Lite (the manuscript's B2, Stage 2) has never been run. No number in this report or in any earlier report comes from it. It is proposed as the next experiment: a minimal v0 (scalar geometric compatibility maps → one shared 1×1 head → score + α · gate · energy, zero-initialized) compared against its own α = 0 control, matched seed and sample order. It is not a result and not a track.

For each reference view: zero depths with confidence ≤ prob_thresh; back-project every view, the reference included; sample each view's 3D point at the reference pixel's reprojection; count views whose point lies within dist_thresh of the reference point; keep pixels with ≥ num_consist such views; output the mean of the consistent points.
Fusion thresholdsGEOMVSNET_PROB_THRESH, _DIST_THRESH, _NUM_CONSISTConfidence > 0.3. Geometric check: world-space distance < 0.2 mm between the reference point and the reprojected source point. View count ≥ 4 consistent views, the reference itself included (≥ 3 source views). There is no separate pixel-reprojection threshold and no separate depth-difference threshold: the single 3D-distance test plays both roles. The thresholds are the same for all scans; there is no per-scan tuning. The config can override them (eval.fusion), but no reported run does.

5.3 CL-MVSNet re-evaluation

Released point clouds score 0.438 under our evaluator vs 0.329 as published; we attribute the gap to fusion settings but have not reproduced the published number.
Our evaluator: 0.446 / 0.431 / 0.438 (acc / comp / overall, 22 scans). Published: 0.329. We have not verified the published 0.329.

Provenance of the 0.438 (read from disk for this report). The .ply files in ../cl_mvsnet_eval/outputs/ were generated locally on 2026-06-20 by running CL-MVSNet's released pretrained model and its own pcd filter, then scored with the official DTU script (../eval.sh → ../official_paper_results.txt, mean of 22 scans 0.4456 / 0.4312 / 0.4384). Our in-repo metric port reproduces those per-scan numbers. The saved depth maps are 640×480, while CL-MVSNet's test script sets --img_size 1184 1600. Test resolution is therefore a second, unexamined candidate cause of the gap, alongside fusion settings. Neither has been isolated (E4).

Consequence for this proposal: every comparison in this report is made under one evaluator, so comparisons between our runs are valid. Absolute numbers are not comparable to published DTU tables. Track 2(a) turns this into a measured finding (E4, E5 in §6.1).
